When a Release is enough

Quand une Release suffit

Cohort testers are expected to install from Releases without cargo. Build from source only if you already have the toolchain or need to change the tree.

Les testeurs de cohorte sont censés installer depuis les Releases sans cargo. Ne compilez depuis les sources que si vous avez déjà la toolchain ou devez modifier l’arbre.

Toolchain

Toolchain

You will need a Windows 10/11 x64 or Linux x64 host, Rust stable with the wasm32-unknown-unknown target, cmake, ninja, and either an MSVC-compatible environment (Windows) or X11/Wayland plus clang/libclang (Linux). NVIDIA and a CUDA Toolkit (typically 12.x, with nvcc) are needed for the CUDA aos-modeld; omit them when you pass -CpuOnly / CPU_ONLY=1. Plan several GB of disk for target/, plus GGUFs on first run.

Il vous faut un hôte Windows 10/11 x64 ou Linux x64, Rust stable avec la cible wasm32-unknown-unknown, cmake, ninja, et soit un environnement compatible MSVC (Windows), soit X11/Wayland plus clang/libclang (Linux). NVIDIA et un CUDA Toolkit (souvent 12.x, avec nvcc) sont requis pour aos-modeld CUDA ; omettez-les avec -CpuOnly / CPU_ONLY=1. Prévoyez plusieurs Go de disque pour target/, plus les GGUF au premier lancement. 

rustup target add wasm32-unknown-unknown

Clone

Clone

Clone the repository, then work from its root for the packaging scripts below.

Clonez le dépôt, puis travaillez depuis sa racine pour les scripts de packaging ci-dessous. 

git clone https://github.com/azerothl/akasha-os.git
cd akasha-os

Package (recommended)

Paquet (recommandé)

The packaging scripts build release binaries, package WASM modules, and assemble dist/AgentOS-Preview-<ver>-…. GGUFs are skipped with -SkipModels / SKIP_MODELS=1 and download on first run instead.

Les scripts de packaging compilent les binaires release, empaquetent les modules WASM et assemblent dist/AgentOS-Preview-<ver>-…. Les GGUF sont omis avec -SkipModels / SKIP_MODELS=1 et se téléchargent au premier lancement. 

# Windows (CUDA tester artefact)
.\packaging\build-preview.ps1 -SkipModels -RequireCuda
# Windows (no CUDA toolkit on the build host)
.\packaging\build-preview.ps1 -SkipModels -CpuOnly

# Linux
SKIP_MODELS=1 REQUIRE_CUDA=1 ./packaging/build-preview.sh
CPU_ONLY=1 SKIP_MODELS=1 ./packaging/build-preview.sh

Then set AOS_HOME to the dist folder and run bin/aos-session, or treat the tree like a Release install. Optional Linux container build: packaging/docker-build-linux.sh.

Ensuite pointez AOS_HOME sur le dossier dist et lancez bin/aos-session, ou traitez l’arbre comme une install Release. Build Linux optionnel en conteneur : packaging/docker-build-linux.sh.

Dev run

Run de développement

From the repo root after a successful release build of the Preview crates (or after build-preview.*), you can run the session crate directly. NVIDIA is recommended; a CPU-only aos-modeld boots without a GPU.

Depuis la racine du dépôt après un build release des crates Preview (ou après build-preview.*), vous pouvez lancer la crate session directement. NVIDIA est recommandé ; un aos-modeld CPU-only démarre sans GPU. 

# Windows
$env:AOS_HOME = (Resolve-Path .)
cargo run -p aos-session --release

# Linux
export AOS_HOME="$(pwd)"
cargo run -p aos-session --release
